## ১. সিদ্ধান্ত

### ক. আপনার নির্দেশে চূড়ান্ত হওয়া বিষয় (আগের প্রশ্নগুলোর উত্তর)

| বিষয় | চূড়ান্ত সিদ্ধান্ত |
|---|---|
| রোল | super_admin > ceo > admin_staff (৭ সাব-রোল) > owner > staff; ক্লায়েন্ট শুধু টোকেন লিংক। accountant, affiliate, reseller রোল নেই। |
| ফাইল স্টোরেজ | টেক্সট ও হিসাব সবসময় Supabase। ফাইল: প্রতিষ্ঠান নিজের Google Drive লিংক করলে Drive-এ, না করলে Supabase Storage-এ। সব ফাইল আপলোডের আগে AES-256-GCM। `storage_provider` প্রতিটি ফাইলে। প্রদানকারী না পেলে স্বয়ংক্রিয়ভাবে অন্যটিতে; মাইগ্রেশন টুল থাকবে। |
| গেটওয়ে | ১৬টি প্রসেসর শুরু থেকেই (তালিকা §৫.৪)। |
| মুদ্রা | সব হিসাব USD, `numeric(18,4)`, JavaScript Number নয়। |
| টেস্ট ফাইল | নেই। যাচাই হবে স্ক্রিপ্ট, SQL অ্যাসারশন ও VERIFY চেকলিস্টে। |
| VPN/প্রক্সি/Tor | সাইন-আপ, পেমেন্ট, KYC, অ্যাডমিনে ব্লক; লগইনে ফ্ল্যাগ + 2FA। |
| লগইন লক | পরপর ২ ভুল (পাসওয়ার্ড বা 2FA) → ২ ঘণ্টা লক (বিস্তারিত §৭.৩)। |
| অ্যাপ্রুভাল | staff → CEO → super_admin চেইন; `approval-rules.ts`-এ প্রতিটি অ্যাকশনের লেভেল। |
| শুরুতে লাগবে | Supabase, Netlify, Cloudflare Turnstile, SMTP, Google Cloud OAuth ক্লায়েন্ট (গ্রাহকের Drive লিংকের জন্য), VPN/Proxy/Tor ডেটা সোর্স। প্রসেসরের কী ড্যাশবোর্ড থেকে বসবে। |

### খ. যে বিষয়ে ডিফল্ট ধরে এগোনো হয়েছে (বদল চাইলে জানাবেন)

| বিষয় | ডিফল্ট |
|---|---|
| সব প্রসেসরের API কী | প্ল্যাটফর্ম-স্তরে শুধু super_admin বসাবে; owner নিজের কী বসাবে না, শুধু সক্রিয় প্রসেসর/মেথড থেকে বাছাই করবে। |
| MoR | কোড দুই মোড সমর্থন করবে (সরাসরি owner-এর কাছে / প্ল্যাটফর্ম হয়ে)। কোনটি চালু হবে কনফিগে। |
| লক-গণনা | পাসওয়ার্ড ও 2FA ভুল একই কাউন্টারে; সফল পূর্ণ লগইনে কাউন্টার শূন্য। |
| 3DS ছাড়া রিভিউ-হোল্ড | অথরাইজেশন সর্বোচ্চ ৭২ ঘণ্টা ধরা থাকবে (কনফিগ), তারপর স্বয়ংক্রিয় বাতিল। |
| সেশন কুকি | `SameSite=Lax` + CSRF টোকেন (প্রসেসর/OAuth থেকে ফেরার রিডাইরেক্টের জন্য)। |
| ইনভয়েস নমুনা | স্ট্যান্ডার্ড US লেআউট; নমুনা দিলে সেটি অনুসরণ। |
| সরকারি e-invoice পোর্টাল | অন্তর্ভুক্ত নয়; ট্যাক্স রেট ও লাইন ট্যাক্স আছে। |
| ডেটা অঞ্চল | একক অঞ্চল (Singapore); স্কিমায় `data_region` কলাম। |
| Solo মোড | শুরুতে CEO না থাকলে super_admin একাই অ্যাপ্রুভ করতে পারবে (সেটআপ উইজার্ডে নির্বাচন)। |
| Payoneer ক্ষমতা | অফিসিয়াল ডকুমেন্টেশন যা সমর্থন করে ঠিক তাই (পে-আউট-কেন্দ্রিক হতে পারে); অসমর্থিত অপারেশন নকল করা হবে না। |

## ২. ব্যবহারকারীর ধরন ও কাজের ধাপ

### ২.১ রোল

| রোল | কে | কী করতে পারে | অ্যাপ্রুভাল |
|---|---|---|---|
| **super_admin** | আপনি | সবকিছু, ইমপারসোনেশন (সময়সীমা + লগ), ফিচার ফ্ল্যাগ, গেটওয়ে | L3 — চূড়ান্ত |
| **ceo** | প্ল্যাটফর্মের অপারেশনাল প্রধান | টেন্যান্ট/প্ল্যান/পে-আউট/KYC চূড়ান্ত রিভিউ — কিন্তু সব কিছু super_admin অ্যাপ্রুভাল সাপেক্ষে | L2 |
| **admin_staff** | ৭ সাব-রোল: kyc_reviewer, payment_processor, support_agent, content_manager, compliance_officer, fraud_analyst, finance_analyst | কেবল নিজ এলাকা; প্রতিটি অ্যাকশনে CEO/super_admin অ্যাপ্রুভাল | L1 |
| **owner** | গ্রাহক (ফ্রিল্যান্সার/ব্যবসা) | নিজের কোম্পানির সব ডেটা, স্টাফ, ব্র্যান্ডিং, গেটওয়ে, KYC, পেরোল | — |
| **staff** | owner-এর কর্মচারী | owner যে পারমিশন দেয় সেটুকু; **খসড়া করে, owner অনুমোদন করে পাঠায়** | owner অনুমোদন |
| **client (রোল নয়)** | ইনভয়েস গ্রহীতা | অ্যাকাউন্ট ছাড়াই HMAC টোকেন লিংকে ইনভয়েস দেখা, পেমেন্ট, এস্টিমেট অনুমোদন, চুক্তি সই, রসিদ ডাউনলোড | OTP ঐচ্ছিক |
| **employee (রোল নয়)** | owner-এর পেরোল কর্মচারী | টোকেন লিংকে পে-স্লিপ ও ছুটির আবেদন (Part 8 A7) | — |

### ২.২ প্রধান কাজের ধাপ

**(ক) নতুন গ্রাহক (owner)**
সাইন-আপ (Turnstile + disposable-email ব্লক) → ইমেইল ভেরিফাই → ২FA সেটআপ → অনবোর্ডিং উইজার্ড (কোম্পানি, ইন্ডাস্ট্রি প্রিসেট, লোগো/রঙ, ইনভয়েস নম্বর ফরম্যাট, ট্যাক্স) → প্রথম ক্লায়েন্ট → প্রথম ইনভয়েস → গেটওয়ে কানেক্ট (বা KYC জমা) → ইনভয়েস পাঠানো → টাকা পাওয়া।

**(খ) ইনভয়েস থেকে টাকা**
ইনভয়েস খসড়া → (staff হলে) owner অনুমোদন → নম্বর বরাদ্দ (গ্যাপহীন) → PDF স্ন্যাপশট → ইমেইল/WhatsApp-এ টোকেন লিংক → ক্লায়েন্ট দেখে → পেমেন্ট → ওয়েবহুক → ইনভয়েস `paid` → রসিদ → (MoR হলে) ওয়ালেটে জমা → হোল্ড পিরিয়ড → পে-আউট।

**(গ) ক্লায়েন্ট (লগইন ছাড়া)**
ইমেইলের লিংক → (ঐচ্ছিক OTP) → ইনভয়েস দেখা, PDF ডাউনলোড → পেমেন্ট পদ্ধতি বাছাই → চেকআউট → রসিদ। মেয়াদ শেষ হলে "নতুন লিংক অনুরোধ" পেজ।

**(ঘ) KYC**
owner ডকুমেন্ট আপলোড (এনক্রিপ্টেড, ম্যালওয়্যার স্ক্যান) → kyc_reviewer রিভিউ → CEO চূড়ান্ত অনুমোদন → ফিচার আনলক (MoR/পে-আউট)।

**(ঙ) অ্যাডমিন অ্যাপ্রুভাল**
admin_staff অনুরোধ তৈরি → CEO → (গুরুতর হলে) super_admin; SLA পেরোলে এসকেলেশন; ছুটিতে থাকলে ডেলিগেশন; সম্পূর্ণ চেইন অডিটে।

**(চ) ডিসপিউট**
গেটওয়ে ওয়েবহুক → ডিসপিউট কেস → এভিডেন্স প্যাক অটো-জেনারেট (ইনভয়েস, সম্মতির প্রমাণ, টাইমলাইন, অডিট হ্যাশ) → ডেডলাইনের আগে জমা → ফল (won/lost)।

**(ছ) মাসিক পেরোল (owner)**
কর্মচারী যোগ → বেতন কাঠামো → পে-রান → অ্যাপ্রুভাল → পে-স্লিপ PDF → পেমেন্ট → জার্নাল এন্ট্রি অটো-তৈরি।

## ৩. পেজ / স্ক্রিন তালিকা

(প্রতিটি পেজে লোডিং, এরর, খালি ও সাকসেস — চার অবস্থা বাধ্যতামূলক; মোবাইল ৩২০px; ডার্ক মোড)

### ৩.১ পাবলিক (≈৪৫) — ফেজ ১ থেকে ক্রমে
- মূল: হোম, ফিচার, প্রাইসিং, ইন্ডাস্ট্রি পেজ, কিভাবে কাজ করে
- কোম্পানি: আমাদের সম্পর্কে, যোগাযোগ, ক্যারিয়ার, ব্লগ (লিস্ট + পোস্ট)
- লিগ্যাল (CMS): Terms, Privacy, Refund Policy, Cookie, DPA, AUP
- সাপোর্ট: হেল্প সেন্টার, FAQ, স্ট্যাটাস পেজ, রোডম্যাপ
- টুল/লিড: ফ্রি ইনভয়েস জেনারেটর, ক্যালকুলেটর (ট্যাক্স, ফি), টেমপ্লেট লাইব্রেরি
- ইউটিলিটি: 404, 500, মেইনটেন্যান্স, `sitemap.xml`, `robots.txt`

### ৩.২ অথ (`(auth)`)
লগইন, সাইন-আপ, ইমেইল ভেরিফাই, পাসওয়ার্ড ভুলে গেছি/রিসেট, ২FA চ্যালেঞ্জ, ২FA সেটআপ, ব্যাকআপ কোড, নতুন ডিভাইস নিশ্চিতকরণ, স্টাফ ইনভাইট গ্রহণ।

### ৩.৩ ড্যাশবোর্ড (owner/staff)
- **হোম**: রেভিনিউ, পাঠানো বনাম পেইড, ওভারডিউ, কুইক অ্যাকশন
- **ইনভয়েস**: লিস্ট, নতুন/এডিট, বিস্তারিত, প্রিভিউ, রিকারিং, ক্রেডিট/ডেবিট নোট, প্রোফর্মা, কিস্তি
- **এস্টিমেট**: লিস্ট/এডিট/ইনভয়েসে রূপান্তর
- **ক্লায়েন্ট**: লিস্ট, প্রোফাইল, স্টেটমেন্ট, মার্জ, ইমপোর্ট
- **পেমেন্ট**: পেমেন্ট লিস্ট, রিফান্ড, পেমেন্ট লিংক, ডিসপিউট
- **ওয়ালেট**: ব্যালেন্স, ট্রানজ্যাকশন, পে-আউট রিকোয়েস্ট
- **প্রোডাক্ট/ইনভেন্টরি/সাপ্লায়ার/পারচেজ অর্ডার**
- **প্রজেক্ট ও টাইম ট্র্যাকিং**

### ৪.৫ গুরুত্বপূর্ণ ডিজাইন সিদ্ধান্ত
- **ওয়ালেট = ডাবল-এন্ট্রি লেজার** (ব্যালান্স কলাম নয়; ব্যালান্স = লেজারের যোগফল), Serializable ট্রানজ্যাকশন।
- **ইনভয়েস নম্বর**: `pg_advisory_xact_lock(hash(company_id,'invoice'))`, গ্যাপহীন; ভয়েড হলে নম্বর পুনর্ব্যবহার নয়, "void" থাকবে।
- **ইনভয়েস স্ন্যাপশট**: পাঠানোর সময় PDF + JSON অপরিবর্তনীয় কপি; পরে এডিট করা যাবে না (ক্রেডিট নোট দিয়ে সংশোধন)।
- **টোকেন**: ডেটাবেসে শুধু হ্যাশ, লিংকে ১২৮-বিট র‍্যান্ডম + HMAC; PII নেই।
- **টাকা**: কোডে `decimal.js`, JS `Number` নয়।
- **কার্ড পরিচয়**: কার্ড নম্বর নয়; প্রসেসরের ফিঙ্গারপ্রিন্ট বা ভল্ট টোকেন, HMAC করে সংরক্ষণ।
- **লক স্টেট**: ইমেইলের HMAC কী দিয়ে ডেটাবেসে; অজানা অ্যাকাউন্টও একই আচরণ।
- **প্রসেসর ক্রেডেনশিয়াল**: AES-256-GCM, কী শুধু এনভায়রনমেন্টে; ক্লায়েন্টে কখনও ফেরত যায় না।
- **ফাইল প্রদানকারী**: প্রতিষ্ঠান ধরে রানটাইমে `resolveProvider(companyId)`।

### ৬.২ লাইভের জন্য যা লাগবে
1. Supabase প্রজেক্ট (URL, anon key, service role key)।
2. Netlify সাইট।
3. Cloudflare Turnstile (site key, secret)।
4. SMTP (হোস্ট/পোর্ট/ইউজার/পাসওয়ার্ড অথবা প্রদানকারীর API কী) ও প্রেরক ডোমেইনের SPF/DKIM/DMARC।
5. Google Cloud OAuth ক্লায়েন্ট (গ্রাহকের Drive লিংকের জন্য; লিংক ঐচ্ছিক)।

7. তিনটি গোপন কী (পরিবেশ ভেরিয়েবল): `ENCRYPTION_KEY`, HMAC টোকেন সিক্রেট, অডিট সাইনিং কী।
8. প্রসেসরের কী এনভায়রনমেন্ট ফাইলে নয়; সুপার অ্যাডমিন ড্যাশবোর্ডের প্রসেসর পেজ থেকে বসবে।

### ৭.২ মডিউল-ভিত্তিক acceptance criteria
