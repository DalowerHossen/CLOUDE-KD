# STEP 02 decisions

- D1 (2026-10-15): The owner instructed to start STEP 02 while the security jobs on `integration` were still being repaired. The fixes (commit 11723d8) live on the session branch, which contains `integration`. STEP 02 is built on this branch.
- D2 (02.4): PostgREST cannot keep a PostgreSQL transaction open across calls and no PostgreSQL driver is in the dependency baseline. The locks contract is therefore implemented with lease rows (`lock_leases`, service role only; functions `kd_acquire_lease` and `kd_release_lease`) and one SQL function for versioned updates (`kd_update_with_version`). Multi-statement atomic work is written as SQL functions called with rpc; `withTransaction` retries serialization failures and deadlocks. The table `lock_leases` is added to the STEP 02 table list (OWNERSHIP_MAP section 4 update requested from the Integrator in HANDOFF).
- D3 (02.7b): `lib/api/with-api.ts` (STEP 01 file) read `routeContext.params` without awaiting it, but Next.js 16 passes route params as a promise, so every dynamic route would have failed validation. Fixed with a minimal change (await the params, type allows a promise). Reported in HANDOFF for the Integrator.
- D4 (02.8): Handler discovery for jobs and event subscribers. `scripts/gen.mjs` (STEP 01 file) gained one section that collects `workers/<step>/<name>.job.ts` (export `jobHandler`) and `workers/<step>/<name>.event.ts` (export `eventHandler`) into `services/jobs/handlers.generated.ts`. Types: `services/jobs/handler-types.ts`. An event is re-delivered to all of its handlers when one fails, so handlers must be idempotent.
- D5 (02.8): Cron fragments use one file per job: `cron/jobs/s02-worker-tick.ts` (every minute), `s02-approval-escalation.ts` (5 minutes), `s02-audit-integrity.ts` (15 minutes), `s02-queue-purge.ts` (daily).
