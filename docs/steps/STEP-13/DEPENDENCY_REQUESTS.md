# STEP 13 - Requests to the Integrator

**R1 Token identity for expired and revoked links (`types/contracts/tokens.ts`, `services/security/token-service.ts`).** `TokenVerification` for `expired` and `revoked` carries only the reason. Please add `id`, `docType`, `docId` and `companyId` to those two cases so the portal can offer a re-request without its own lookup. Until then STEP 13 uses `kd_portal_token_lookup` (decision D3).

**R2 Public payment link for the portal (`services/payment/links.ts`).** The invoice page's "Pay now" creates a link with a fixed portal actor (decision D8). Please add `createClientPaymentLink({ companyId, invoiceId, validHours })` that needs no actor, so STEP 13 can use it.

**R3 Code-protected estimate links (`services/estimate/public.ts`).** `getEstimateByToken` and `decideEstimate` throw `ForbiddenError` for a token that needs a code, because they cannot know that the portal already checked the code. Please add an option (for example `{ otpVerified: true }`, set only by the portal after `resolvePortalAccess` returned `ok`) that skips that refusal. Until then such an estimate link shows as unavailable (decision D11).

**R4 Forward warning in the invoice emails (`emails/invoice/*.tsx`).** The invoice, estimate and reminder messages hold a private link but do not warn against forwarding. Please render `ForwardNotice` (exported from `emails/client/client-frame.tsx`) at the end of `invoice-sent.tsx`, `estimate-sent.tsx` and `invoice-reminder.tsx`.

**R5 Portal-only custom domains (`proxy.ts`).** A request whose host is a verified custom domain of a company (see `tenantForHost` in `services/branding/domain.ts`) should only be allowed to reach `/i`, `/pay`, `/e`, `/r`, `/hub`, `/c`, `/expired`, `/api/portal`, `/api/payment-links` and static files; every other path on that host should answer 404. The host lookup needs the database, so it cannot run in the Edge runtime: a cached call to a small internal route, or a Node.js proxy, is needed.

**R6 Dispute details in the event (`services/payment/webhook-core.ts`, `lib/payment/adapters/*/webhook.ts`).** `dispute.opened` carries only `paymentId`, `invoiceId`, `processorId`, `eventId` and `disputeId`. Please add, when the processor gives them, `reasonCode` (text), `dueBy` (ISO time of the answer deadline) and `disputedAmount` (decimal text) to the normalized payload and to the published event. `services/dispute/intake.ts` already reads these three names.

**R7 Submit evidence through the adapter (`types/contracts/payment-adapter.ts`).** Please add an optional `submitDisputeEvidence(context, input)` to `ProcessorAdapter` (and implement `evidenceFormat` per processor after reading its documentation), so that `services/evidence/packs.ts` can send a pack to the processor by API. Until then the owner sends the downloaded pack by hand.

**R8 Ownership additions and the portal layout (`docs/execution/OWNERSHIP_MAP.md`, `app/(client-portal)/layout.tsx`).** `scripts/check-ownership.mjs 13` flags files STEP 13 needs that no row covers. Please add to row 13: `app/(dashboard)/client-mail/**` (owner pages for client messages, link requests and branding), `config/s13-*.ts` (portal constants), `workers/s13/**` (the two event workers). Also please make `app/(client-portal)/layout.tsx` (STEP 01) return the component `BrandedPortalLayout` from `components/client/branded-portal-layout.tsx` for its children: it gives a company's own domain the company name in the page header and, on white-label plans, no platform mark (decision D18). The generated barrels `config/approval-rules.generated.ts`, `cron/schedule.generated.ts`, `lib/bootstrap.generated.ts`, `lib/i18n/strings/en.ts` and `services/jobs/handlers.generated.ts` were regenerated with `npm run gen`, as earlier STEPs did; the Integrator regenerates them at merge.
