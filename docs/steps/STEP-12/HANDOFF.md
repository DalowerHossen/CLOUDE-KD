Known limits per processor are in section C of each `.verify.md` and section 12 of each `.md`. In short:
- **NMI:** Collect.js submit trigger is undocumented on the readable pages (B1); the Payment Component needs an npm package (R1); the REST live host is not stated (B2); no idempotency header.
- **Adyen:** no payment lookup call (`getTransaction` unavailable; R3 for resuming pending payments); immediate capture only; refunds asynchronous; default live endpoint only; Drop-in CSP hosts to be recorded in the sandbox run.
- **Paddle:** Paddle.js pages unreachable (B5); five-second webhook window; refunds may wait for Paddle's review.
- **FastSpring:** Checkout Components are Beta and enabled by FastSpring on request; order is bound to the invoice by amount and currency only; a multi-event webhook maps its first known event.
- **PayPro Global:** API calls need the platform server address whitelisted and the secret key generated by PayPro Global; no event id in the IPN (a generated id is used); the payer types the order number.
- **Payoneer:** nothing built; which product (accepting payments or payouts) must be chosen.
- **Rapyd:** one-step card sale only; only three card decline codes mapped.
- **Custom:** webhook body must have a fixed neutral shape; the gateway must return the invoice reference; hosted flow with a typed payment reference.
