# PayPro Global - documentation record

## 1. Sources read
Read in this session on 2026-10-18 (UTC) from PayPro Global's own documentation site https://developers.payproglobal.com (Docusaurus pages; the text was extracted from each page).
- API: API overview (authentication and the list of calls), Orders: Get Order Details, Get List, Do Reference Charge, Do Refund, Do Partial Refund.
- Checkout pages: Checkout Page Overview, Dynamic Checkout Links (dynamic settings and AES encryption, with C#, PHP and Python samples), URL Parameters, Scramble URL, Thank You Page Redirect.
- Webhooks: Webhook/IPN (types, security, every parameter, retries).
Not read: the pop-up and iframe checkout pages (their script API), the sandbox/test-mode guide beyond the URL parameters, the subscription pages (subscriptions are not used).

## 2. Authentication and credential fields
API calls: `POST https://store.payproglobal.com/api/<Group>/<Method>`, JSON; the request body carries `vendorAccountId` and `apiSecretKey` (there is no header). **Calls are verified by IP: the platform's server addresses must be whitelisted by PayPro Global support** (email to the account manager) and the API secret key is first generated by them. Credential fields (names only): `vendorAccountId` (not secret; Account settings, Business info), `apiSecretKey` (secret; Store settings, General settings, Integration), `validationKey` (secret; the key of the IPN `SIGNATURE`), `productId` (the product whose dynamic settings are enabled and encrypted), `encryptionKey` (secret; exactly 32 characters, the Scramble URL / dynamic settings key), `encryptionIv` (secret; exactly 16 characters), `testSecretKey` (secret, optional; the `secret-key` that test links need when the account defines one).

## 3. Environments
One host (`https://store.payproglobal.com`). Test mode is a property of the checkout link (`use-test-mode=true`, which works only together with the account's `secret-key` when one is defined) and of the order (`isTestMode` in order details, `TEST_MODE` in the IPN). The adapter uses test mode for the sandbox environment, never for live, and refuses an order whose `isTestMode` differs from the environment. List calls hide test orders unless asked.

## 4. Secure form
PayPro Global is a hosted checkout (merchant of record): no card data and no token API. The server builds a **dynamic checkout link** and the payer opens it (a new window, never inside the platform page): `https://store.payproglobal.com/checkout?products[1][id]=<productId>&products[1][data]=<encrypted>&currency=USD` (plus `use-test-mode=true&secret-key=<testSecretKey>` in the sandbox only). The encrypted text is the dynamic settings query string (`Name`, `Price[USD][Amount]`, `LinkExpiration` in UTC, and the custom field `x-KdInvoice`) encrypted with AES-256-CBC, PKCS7, the 32 character key and the 16 character IV, URL-safe Base64 (`+` to `-`, `/` to `_`). Dynamic settings and encryption must be enabled in the product (Product Setup, Pricing Configuration, Dynamic Settings).
The platform has no return route for the PayPro Global thank-you redirect (a static URL configured in the page template, which receives the checkout query string by GET and the order data by POST). The form therefore asks the payer for the **order number shown on the PayPro Global thank-you page** and hands that number to the platform as the payment token; the server verifies it (section 5), so a wrong or foreign number is refused. A return route would remove the manual step (request R4).

## 5. Operations (REST, JSON)
- Create the payment: no API call; `createCheckoutSession` encrypts the dynamic settings (above) and returns only the link.
- Verify (`authorize` and `charge`, same code; `supportsAuthCapture` is false): `POST /api/Orders/GetOrderDetails` `{ orderId, dateFormat: "a", vendorAccountId, apiSecretKey }`; answer `{ response: { orderStatusId, billingCurrencyCode, billingTotalPrice, billingTotalTaxes, billingRefundedAmount, customFields, isTestMode, creditCardLast4, creditCardExpirationDate, paymentMethodName, orderItems[] }, errors, isSuccess }`. Status ids: 1 Waiting, 2 Canceled, 3 Refunded, 4 Chargeback, 5 Processed. The adapter requires status 5, `isTestMode` matching the environment, USD, the custom field `KdInvoice` equal to the invoice id, and `billingTotalPrice` (excluding tax) or price plus taxes equal to the invoice amount.
- No authorization or capture, no void.
- Refund whole: `POST /api/Orders/DoRefund` `{ orderIds: [id], refundReason, vendorAccountId, apiSecretKey }`; answer `response[]` with `isRefundSuccessful` and `refundNotice`. "If the order is linked to a subscription, a refund terminates it." Partial: `POST /api/Orders/DoPartialRefund` `{ orderItemId, refundAmount (number), refundReason, changeSubscriptionPrice: false, cancelSubscription: false, ... }`; answer `response.isRefundSuccessful`.
- Connection test: `POST /api/Orders/GetList` `{ skip: 0, take: 1, search: {}, ... }` - `isSuccess` true means the credentials and the server address were accepted.
- Our `processorTransactionId` is the order id. Amounts are JSON numbers (bare, printed from cents).

## 6. 3D Secure
Handled inside PayPro Global's checkout; no 3DS result is exposed in the pages read. `supportsThreeDS: false`; every result is `{ requested: false, completed: false, authenticated: false, liabilityShift: null }`.

## 7. Card identity (REQ-CARD)
No fingerprint. For a card order: `paymentMethodName|last4|expiry` (type `fingerprint`); the IPN also carries the BIN, which is not used because order details do not. Non-card payments give no identity.

## 8. Decline mapping
Order details carry `orderStatusReason` for a canceled order and the call-reference answer carries `orderDeclineReason`; no code list was read, so every canceled order is `other`.

## 9. Webhooks (IPN)
Set per product (Store settings, Product setup, IPN URL). `POST`, `Content-Type: application/x-www-form-urlencoded`, HTTP 200 = success; failed deliveries are retried every 30 minutes, three times. **Signature**: field `SIGNATURE` = SHA-256 (hex) of the concatenation `ORDER_ID + ORDER_STATUS + ORDER_TOTAL_AMOUNT + CUSTOMER_EMAIL + VALIDATION_KEY + TEST_MODE + IPN_TYPE_NAME`, taken verbatim from the posted fields. The older `HASH` (MD5) is not used. The sender addresses are 198.199.123.239, 157.230.8.40 and two IPv6 addresses (the adapter cannot check addresses).
- Events used: `OrderCharged` -> payment.captured; `OrderDeclined` -> payment.failed; `OrderRefunded`, `OrderPartiallyRefunded` -> payment.refunded; `OrderChargedBack` -> dispute.opened; `OrderChargedBackWon` -> dispute.closed; everything else (including `OrderOnWaiting`) -> unknown.
- `processorTransactionId` = `ORDER_ID`. The IPN has **no event id**: the adapter builds `IPN_TYPE_ID:ORDER_ID:ORDER_ITEM_ID:ORDER_REFUNDED` (a retry carries the same values). The time of receipt is used. A multi-product order sends one IPN per product.

## 10. Idempotency
No idempotency key exists in the API. The link carries a `LinkExpiration` (24 hours); creating a link is local and harmless; `authorize` and `charge` read the order; a repeated refund returns the stored state when the order is already refunded.

## 11. Test data
Test links use `use-test-mode=true` (and `secret-key` when the account defines one). Card numbers for the test mode were not on the pages read.

## 12. Limits and capabilities
`supportsAuthCapture` false; `supportsThreeDS` false; `supportsRefund` true; `supportsPartialRefund` true (first order item); `supportsRecurring` false (subscriptions exist, not used); `supportsPayout` false; **`isMerchantOfRecord` true** (PayPro Global sells to the payer, adds and remits tax, pays the merchant after fees). Currency USD. A partial refund can end a subscription only if asked; the adapter never asks. The order number is typed by the payer (section 4). The API server address must be whitelisted. Dynamic settings and encryption must be enabled on the product.

## 12a. Content security policy
The platform page does not load PayPro Global scripts or frames; the checkout opens in a new window, so no origin is added.

## 13. Open questions
1. How `customFields` are keyed in the order details answer (with or without the `x-` prefix); the adapter accepts either, case-insensitive.
2. Whether a dynamic `Price[USD][Amount]` is tax-exclusive (the adapter accepts the price alone or the price plus taxes).
3. The test card numbers and whether the test order carries `isTestMode: true` in order details.
4. The format of `ORDER_PLACED_TIME_UTC` and `ORDER_CUSTOM_FIELDS` in the IPN.
5. Whether `HASH` and `SIGNATURE` are lower-case hex (the adapter compares case-insensitively).
6. Whether `LinkExpiration` is enforced when the link is encrypted.
