## A. Local checks (run, passing)
`npx tsx --conditions=react-server scripts/verify/step12-payproglobal.ts` -> 11 checks passed. A fake HTTP transport answers with the shapes of PayPro Global's reference pages (docs/processors/payproglobal.md). It proves:
- contract: merchant of record, one-step sale (`charge` present, no capture or void), USD only, credential field patterns;
- amount numbers are printed bare from cents (`20.00`, `0.07`);
- checkout link: no API call; the exact link (`products[1][id]`, encrypted `products[1][data]`, `currency`, test mode and test secret key in the sandbox only); the encrypted text decrypts (AES-256-CBC, ASCII key and IV, URL-safe Base64) to the invoice custom field, name, `Price[USD][Amount]` as `120.50` and a UTC expiry; no secret is in the answer; a missing product id, a wrong key length and an invoice reference with unsafe characters are refused;
- `charge` and `authorize` read the order (`GetOrderDetails` body with account id as a JSON integer): processed, test mode matching the environment, USD, invoice custom field (with or without the `x-` prefix, as object or list), amount equal to the price or price plus tax; waiting, canceled, a live order in the sandbox, a test order on a live account, another currency, another amount, another invoice, no invoice, an unknown order, a malformed number, 403 (whitelist hint) and 5xx are refused;
- refund: whole (`DoRefund`), partial (`DoPartialRefund` with the first item and a bare number), a refused refund as declined, too large, a partly refunded order refunded in part, an already refunded order answered from the stored state, not processed refused before any call;
- lookup, states (chargeback marked), card identity, connection test (success, 401 without the key text, not ok, missing key);
- webhooks: SHA-256 signature over the posted fields (upper-case hex accepted); a wrong key, a changed amount, a changed signature, a missing signature, a changed test flag, an empty body and a missing key are refused; event mapping for charge, decline, refunds, chargeback, won chargeback, unrelated events, and the generated event id.

## C. Known limits
- The payer types the order number from PayPro Global's confirmation page (a thank-you POST return route would remove this step: STEP 12 request R4).
- The API calls need the platform server address whitelisted by PayPro Global support, and the API secret key is generated by them.
- Dynamic settings and encryption must be enabled on the product; the test secret key appears in a sandbox link (sandbox only).
- The IPN has no event id; the generated id can merge two partial refunds of the same cumulative amount.
- No idempotency key, no decline codes (every refusal is `other`), card identity has no BIN or fingerprint.
- PayPro Global is the seller of record: its terms, tax handling and payout timing differ from the other processors; a refund terminates a linked subscription.
